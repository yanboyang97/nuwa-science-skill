## 本次设计及其可失败之处

| 设计 | 原因与适用前提 | 出现什么结果需修改 |
|---|---|---|
| 以“研究中的主张”而非整篇论文作为连接单位 | 一篇论文可同时支持某一判断、限制另一判断 | 一条边无法指出双方具体主张，或把局部反证扩成整篇被推翻 |
| 关系分为原文明确、综合推断、待核验 | 避免把新解释冒充已证实事实 | 读者无法分辨作者与综合者的责任，或图中的推测被写成结果 |
| 允许孤立节点和无法连接的结果 | 材料可能只共享主题，不共享证据链 | 为满足叙事完整而发明桥接机制 |
| 对关键联系补查，不重做全领域搜集 | 本技能的目标是串联选定材料，默认不是系统综述 | 缺少关键材料仍宣称完整，或检索无限扩张而无法交付 |
| 检查共享数据、版本与引用语境 | 多个文本可能仅重复同一依据 | 重复报告被描述为独立支持，引用被误当赞同 |

以上是可检验的设计建议，不是已经证明优于其他流程的方法。

## 创建者场景走查

以下为指令层面的人工推演，不是独立执行评测或真实研究试用。

| 输入 | 走查结果 |
|---|---|
| “把这几篇论文的方法和结论串起来” | 采用研究关系综合默认值，提取主张和条件，输出有双方定位的关系表 |
| “只把这篇摘要翻译成中文” | 不触发串联流程 |
| “按时间排列这些论文，证明后来者继承前人” | 时间顺序可整理；思想传承另查引用语境或原始说明，不由年份推出 |
| A 与 B 共同引用 C，未读 C | 标出来源依赖和未核验，不算三份独立证据 |
| 两篇研究结果不同，但对象与指标不同 | 先对齐条件，保留不能直接比较或尚待验证的解释 |
| 只有标题和摘要，却要求完整机制图 | 给候选联系及阅读边界，尝试取得关键全文；不补造机制 |
| 指定仅用本地四篇论文 | 保持集合内分析，覆盖限制明确，不自动外查 |
