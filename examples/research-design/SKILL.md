# 研究方案与评价设计

从要回答的问题反推最有辨别力且可实施的研究步骤，交付能被检查、执行和修订的方案。方法选择服从问题与资源，不预设所有研究都是随机实验。

## 输入与首次默认说明

必需输入是可辨认的研究问题、假设或待评价方案。已有证据、候选解释、数据/材料、资源和时间限制优先从上下文获取。若目标仍宽泛，先给有边界的小规模方案；只在不同解释会改变核心设计且无法合理选择时集中提问。

首次启用简短说明：“我先围绕核心问题设计最小可行研究，明确比较条件、评价依据和可能改变结论的结果；已有材料优先，未知资源先列假设。研究类型、范围、预算和交付形式都可调整。”然后推进，不要求逐项确认默认配置。

默认随对话语言输出，先给方案和必要的定向方法核查；不自动采集新实验数据或启动昂贵运行。已获执行授权的任务继续按授权推进，不因本技能人为增设批准步骤。未定预算用条件化方案或成本范围，不把未知资源当作无限或为零。

## 资料入口与提取字段

- **问题依据：** 用户研究笔记、原始论文与反证、已有评议；提取目标、已知结果、关键不确定性、竞争解释及其条件。
- **方法依据：** 领域学会/期刊方法指南、原始方法论文、公开协议及作者维护代码；提取前提、输入、操作、指标、失效边界与计算需求。
- **材料条件：** 数据说明与实际可读字段、仪器/软件文档、试点记录、理论假设或史料目录；提取来源、版本、规模、测量单位、访问与使用条件、缺失及误差。
- **计划记录：** 现有协议、预注册、分析计划和变更记录；提取何时见过哪些结果、哪些选择已固定、哪些是探索性修改。

优先适用的已连接工具与本地材料，缺口再查公开原始入口。来源不可得时尝试作者稿、机构库或开放附件；仍缺关键实施细节则给条件化设计，不编造参数、样本量或运行步骤。不同研究类型的专门标准在实际采用时核查，不假设某平台、全文或设备一定可用。

## 设计流程

### 1. 固定要回答什么

写明研究问题、目标对象与适用域、希望区分的解释、主要产物及“何种结果会改变当前判断”。区分探索、描述、预测、因果比较、机制解释、理论证明和解释性研究；同一项目包含多种任务时，分别指定证据要求。

把必答问题与可选扩展分开。评价一个方法时定义公平的比较对象、适用场景和有意义的改善，不能仅为追求较高指标改换问题。

### 2. 选择能回答问题的研究路径

比较合理可行的候选路径，说明为什么选择当前方案及放弃其他路径的代价；一个显然适用的方案不必为了填表强造备选。

| 路径 | 设计重点 |
|---|---|
| 实验或干预 | 实验单位、分配与对照、随机化/区组和盲法的适用性、重复、依从与干扰、结局时间点；区分技术重复与独立样本 |
| 观察分析 | 目标效应、时间起点、入组、暴露/干预和比较、混杂与选择机制、识别假设及敏感性；已有数据关联不能保证因果识别 |
| 预测/工程评价 | 数据划分单位与时间、训练/调参/测试隔离、基线调参机会和资源可比性、泛化场景、误差与成本指标 |
| 理论 | 定义、假设、命题、关键引理与证明路径、可检验的特例/反例；数值验证作为辅助，不能代替一般证明 |
| 仿真 | 模型与参数来源、边界/初值、离散误差和收敛检查、随机性、校准与独立验证数据、现实适用范围 |
| 质性/人文 | 材料选择与访问、语境、研究者立场、访谈/编码或解释路径、负例及竞争解释、证据可追溯性 |

跨领域迁移先核对对象、测量和机制是否对应；形式相似不是适用证据。

### 3. 写清操作与测量

定义变量或概念如何观测、编码或推导，谁/什么是分析单位，材料纳排依据是什么。列出主比较、必要控制与关键干扰；若复合指标可能掩盖变化，保留能解释它的基础测量。

给出足够执行的流程、依赖、版本、输入输出和质量检查。数据清洗、缺失与异常处理规则在看到待检验结果前尽量确定；确需改变时记录理由及影响，不把事后决定改写成预设。

### 4. 设定评价与判定条件

主要评价对应科学问题，次要评价用于解释、稳健性或成本。每个主要结论写清：使用什么证据、如何分析、在什么条件下支持、削弱或无法区分候选解释。性能进步、理论成立、可用性和资源收益分别报告。

数量研究根据目标效应、变异、相关结构、设计与错误代价确定精度或功效需求，保留计算依据；缺这些输入时给可核查的假设范围、敏感性方案或试点目标，不默认固定样本量。重复测量或多个随机种子不自动增加独立样本数。

效应大小、区间与实际意义一起解释；若要证明“足够相近”，需有适当等效界限与设计，不能仅靠差异未显著。探索发现标明探索性，保留独立检验或适当推断校正的路径，不用同一数据反复调方案后冒称独立验证。正式预注册或注册报告仅在任务需要时采用，不把登记当作方法质量保证。

### 5. 对方案做失败推演

检查至少最可能使核心结论失效的情形：对照回答了别的问题、测量没有捕捉目标、关键材料不可得、预算不足、泄漏或假设不成立。为适用的风险写“发生条件—如何识别—替代路径—结论如何收窄”。

先安排能检验关键实施假设的小试点，随后才扩大；试点通过不代表研究假设成立。涉及人员、动物或受限材料时，将实际适用的伦理审查、访问和招募条件列为实施依赖，不能伪称已取得。

### 6. 交付可执行版本

默认交付任务摘要、方案正文和简明设计表：

问题/假设｜所需证据｜材料与对照｜操作及分析｜判定条件｜成本和依赖｜失败分支。

标注当前版本、依据与待定参数。若同时交付文字方案与机器可读配置，从保存后的配置重新加载并核对两者的参数值、类型、单位和库中的含义；整数、比例、默认值等形式差异可能改变操作，不能只凭文本相似判定一致。按资源对关键配置做最小语义或运行检查，明确哪些尚未在实际软件中执行。计划、预期结果与已发生结果分开；纯设计任务不填造实验数字。补充最小下一步及其完成标准，必要时说明可选扩展。

## 完成条件与衔接

主要问题都有对应证据获取路径与判定规则、实施依赖和资源假设已说明、关键失效情形有处理方式时完成设计。核心识别前提或材料无法满足时明确“当前方案不能回答该问题”，给出可支持的收窄方案；不要靠增加样本掩盖不可识别或测量失配。

需要修复既有论证时，接收证据审查中的具体缺口；需要实际执行或核验结果时，交接方案版本、固定参数、评价脚本/规则和停止条件。路线选择只需接收方案价值、成本范围、关键依赖和最早决策点，不复制所有研究材料。

组合任务交给执行者前，核对操作、对照和分析是否仍回答上游的同一问题，保留不支持的机制或外推结论。明确首次执行由谁承担，已有结果的复现另记；方案因资源或证据而改版时，列出被改变的估计对象、分析与结论范围，并回传给受影响的问题、假设、写作和路线判断。文件相似或参数可运行不能替代这项语义核对。
